# Theming

Meda ships light mode as the default and dark mode as a selector-based override. Both modes share token names; values change.

## How themes work

The token contract has three layers, defined in `src/styles/tokens.css`:

1. **Layer 0: Color primitives.** Brand, neutral, error, info, success, and warning ramps. These are constant across themes.
2. **Layer 1: Semantic tokens.** `--background`, `--foreground`, `--card`, `--primary`, `--border`, `--ring`, and related tokens. These flip between light and dark.
3. **Layer 2: Shell tokens.** `--shell-header`, `--shell-rail`, `--shell-context`, and panel tokens for application chrome.

## Switching themes

Add the `dark` class or `data-theme="dark"` to a parent element:

```html
<html class="dark">
  ...
</html>
```

Storybook uses `data-theme`, while host apps can use either selector.

## Tailwind dark utilities

Meda's Tailwind v4 theme bridge registers a dark variant for both selectors:

```css
@custom-variant dark (&:is(.dark *, [data-theme="dark"] *));
```

Use `dark:bg-card`, `dark:text-foreground`, and related utilities without extra configuration.

## App token bridge

Existing products can map their brand variables onto Meda's semantic tokens without copying long CSS blocks:

```ts
import { createMedaThemeCss, defineMedaTheme } from '@medalsocial/meda/theme';

const autoTheme = defineMedaTheme({
  appId: 'auto',
  colors: {
    primary: 'var(--hb-brand-500)',
  },
  fonts: {
    body: 'var(--font-body)',
  },
  light: {
    colors: {
      background: 'var(--hb-base-50)',
      foreground: 'var(--hb-base-950)',
    },
  },
  dark: {
    colors: {
      background: 'var(--hb-base-900)',
      foreground: 'var(--hb-base-50)',
    },
  },
});

const css = createMedaThemeCss(autoTheme);
```

Apply the generated CSS under `[data-meda-app="auto"]`, then set that attribute on the app root.

## Auth gradient tokens

The auth shell marketing panel uses dedicated gradient tokens so product branding does not require overriding the entire brand ramp:

```css
:root {
  --auth-gradient-primary: var(--color-brand-500);
  --auth-gradient-secondary: var(--color-brand-700);
  --auth-gradient-base: var(--color-brand-800);
}
```

Override those after importing `@medalsocial/meda/styles.css` when an auth screen needs a custom campaign gradient without changing buttons, focus rings, or other semantic brand usage.
