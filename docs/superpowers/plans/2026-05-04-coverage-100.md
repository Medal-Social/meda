## Architecture

The work is divided into **8 clusters** by directory. Each cluster:

1. Owns a fenced set of files with similar testing patterns.
2. Gets dispatched as one subagent run with full context.
3. Produces one or more commits on `feat/coverage-push`.
4. Includes its own pre-flight (file-level coverage scan), test additions, and post-flight (assert per-file 100%).

Subagent boundary protects context: each cluster reads only its own files, doesn't touch the rest.

## Constraints / things to NOT do

- **Don't touch source code** unless an inherently untestable path needs a small refactor (e.g., extract a helper). Default to writing tests against the existing surface.
- **Don't change the public API** to make code more testable. If the surface is hard to test, that's a signal to refactor in a SEPARATE PR after this one merges.
- **Don't disable strict biome rules** to get tests through. Use the existing patterns (typed mocks, `unknown` casts at boundaries).
- **Don't merge stories or fixtures into the metric** by removing them from the exclude list. Coverage is for shipped runtime code only.

## Subagent dispatch protocol

For each phase:

1. Spawn a subagent with the cluster prompt template.
2. Subagent reads its files, runs `pnpm test:coverage`, identifies gaps, writes tests, commits.
3. Subagent replies with commit SHA and post-cluster coverage.
4. Controller verifies the diff, runs the full suite to confirm no regressions in other clusters, marks the cluster done.
5. If coverage didn't reach 100% on a sub-cluster, spawn a fix-up agent with a tighter brief on the remaining files only.
